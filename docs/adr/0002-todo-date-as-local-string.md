# ADR-0002: `Todo.date`는 브라우저 로컬 날짜 기준 문자열(`"YYYY-MM-DD"`)

- **Status**: Accepted

## Context

ToDo를 "날짜별 일간 목록"으로 관리하려면 각 항목이 어느 날짜에 속하는지 저장해야 한다. 두 가지 방식을 검토했다: ① `Todo.date`를 `DateTime`으로 저장하고 조회 시 서버(UTC) 기준으로 하루 범위를 계산 ② `Todo.date`를 `"YYYY-MM-DD"` 문자열로 저장하고 "오늘"은 클라이언트(브라우저)의 로컬 연/월/일로 결정.

①번은 서버·클라이언트 타임존이 다를 때(특히 자정 근처) 사용자가 보는 "오늘"과 서버가 계산한 "오늘"이 어긋날 수 있다.

## Decision

`Todo.date`는 `String` 타입, `"YYYY-MM-DD"` 포맷으로 저장한다(옵션 A). "며칠"인지는 **브라우저의 로컬 연/월/일**로 클라이언트가 계산해 쿼리스트링/바디로 서버에 전달한다. 조회는 문자열 정확 일치(`where: { userId, date }`)로 처리한다.

날짜 관련 변환/검증은 전부 `src/lib/date.ts`의 순수 함수(`toDateString`, `todayString`, `isDateString`, `addDays` 등)로 집중시키고, `Intl`은 쓰지 않는다(로케일 데이터 환경 의존 회피).

## Consequences

- 타임존 버그를 피하고, "오늘"의 기준이 항상 사용자가 보는 화면과 일치한다.
- 대신 서버 단독으로는 "지금 사용자 로컬 기준 오늘이 며칠인지" 알 수 없다 — 항상 클라이언트가 날짜를 명시해서 요청해야 한다.
- 날짜 범위 쿼리(예: 월별 요약)는 문자열 range(`gte`/`lte`)로 구현한다(`/api/todos/summary`).
- 이 방식을 뒤집고 `DateTime` + 서버 타임존 계산으로 바꾸지 않는다 (`CLAUDE.md` 가드레일 참고).
