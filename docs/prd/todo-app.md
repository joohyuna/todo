# PRD: 일간 ToDo 앱

## 왜 만드는가

날짜 단위로 할 일을 관리하고 싶은 개인용 서비스. 여러 사용자가 각자 계정으로 로그인해 자신의 할 일만 보고 관리한다.

## 사용자

- 자기 자신의 할 일을 날짜별로 기록하고 싶은 개인 사용자. 팀/공유 기능은 없음(1인 1계정, 데이터는 계정 간 완전히 격리).

## 핵심 기능 (구현 완료)

| 기능 | 설명 |
|---|---|
| 회원가입/로그인 | 이메일 + 비밀번호(Credentials), JWT 세션. OAuth 없음 |
| 날짜별 할 일 CRUD | 특정 날짜(`YYYY-MM-DD`)에 할 일 추가/완료 토글/삭제 |
| 날짜 네비게이션 | 어제/오늘/내일 이동, 주간 스트립·월간 캘린더 전환 |
| 완료 시각·통계 | 완료 시각 표시, "완료 N / 전체 M" 카운트 |
| 브랜드 디자인 | 그린 계열 브랜드 컬러, 오렌지 계열 "할 일 있음" 표시 |

세부 구현·데이터 모델은 `docs/architecture/ARCHITECTURE.md` 참고. 각 결정의 배경은 `docs/adr/` 참고.

## Non-goals (현재 범위 밖)

- 여러 사용자 간 공유/협업 (팀 ToDo, 위임 등)
- 미완료 항목의 자동 이월(carry-over) — 각 날짜는 독립적인 목록 (`docs/adr/0005-no-carry-over.md`)
- OAuth 소셜 로그인
- 오프라인/모바일 앱

## 확장 후보 (우선순위 미정, 착수 전)

핵심 흐름 완성 후 후보로 남겨둔 것들. MongoDB + `db push` 구조라 필드 추가 자체는 무손상이므로, 착수 시 각각 독립 RFC로 진행한다.

- **카테고리** — `Todo`에 분류 추가. 후보안: ①`category String?` 자유 입력 ②고정 상수 드롭다운 ③사용자별 `Category` 모델(색상 포함)
- **우선순위**(`priority`), **상세 메모**(`memo`), **태그**(`tags`)
- **미완료 항목 자동 이월** — 현재의 "이월 없음" 결정(ADR-0005)을 뒤집는 것이므로 재검토 필요
- **드래그로 순서 변경** — `Todo.order` 필드는 이미 예약되어 있음
